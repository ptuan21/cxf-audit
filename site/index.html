cxf-audit

A narrow, deep security tool for CXF/CXP — FIDO Alliance's standard for moving passkeys between password managers. Catches zip-slip, zip-bomb, and protocol downgrade issues, from raw archive bytes down to real taint analysis of your Rust, Kotlin, and Swift implementation code.

Why this exists

CXF packages credentials as a zip. The spec doesn't say how to sanitize entry names.

CXF (Credential Exchange Format) exports passkeys/passwords as individually-encrypted files inside a zip archive. Per spec, a credential's identifier is its file name in that archive — and nothing in the spec says how an importer must sanitize that value before writing it to disk. That's the exact setup for zip-slip. cxf-audit exists to catch it before it ships, at every layer where it could hide.

Data

Archive & protocol

scan / assert_safe_archive() flags path-traversal entry names and zip-bomb sizing in real CXF archives; check_version_downgrade() catches silent CXP protocol downgrades.

Syntax

scan-source (tree-sitter)

Parses your Rust/Kotlin/Swift source with real grammars — not regex — and flags known zip-slip antipatterns per language. No external tools required.

Dataflow

Real taint analysis

Semgrep rules that track tainted zip entry data through variables and method chains to the sink, and correctly recognize a proper guard-clause check as safe.

Engineering journal

We tried CodeQL first. It failed for a specific, verifiable reason.

Most write-ups skip the dead end. This one doesn't — the failure is more informative than the feature.

CodeQL Rust Dead end

CodeQL's Rust support (GA since Oct 2025) already ships a purpose-built DotDotCheck sanitizer for exactly .contains(".."), plus pre-modeled sinks/summaries for File::create and Path::join. Should have been a five-minute win. It found nothing.

Root cause, found by reading FlowSummaryImpl.qll and probing a real database directly: getStaticTarget() couldn't resolve .by_index() at all. Isolated with a pure local generic struct (no third-party crate) — its own inherent method resolved fine, but .clone() and .to_uppercase() — the most ordinary trait methods in Rust — didn't. Not a zip-crate quirk; a real, current gap in trait-method resolution. And unfixable from the outside: flow-summary models only attach after a call resolves, confirmed straight from the source.

Semgrep taint mode Partial win

No full type resolution needed — closer to tracking assignments syntactically. First test: does taint flow from .by_index() through .unwrap(), .name(), .to_string(), Path::join(), to File::create()? Yes, clean, on the first try.

The obvious sanitizer syntax Also wrong

pattern-sanitizers: [{pattern: $X.contains("..")}] flagged the safe function too. Cross-checked against Python (Semgrep's most mature taint language) with the identical rule shape — same failure. Not a Rust gap: basic pattern-sanitizers clears taint from the matched expression itself (an unused boolean), not from the variable being checked.

by-side-effect + focus-metavariable Fixed it

The actual mechanism: mark the variable sanitized at the call site, not the call's return value. 

pattern-sanitizers:
  - patterns:
      - pattern: $X.contains("..")
      - focus-metavariable: $X
    by-side-effect: true

Verified working end-to-end in Rust, Kotlin, and Swift (Swift needed one adjustment — bind entry.path to a local let before checking it; inline property-access checks didn't trigger reliably).
